# Реализация задания 1 и ручной запуск

Этот документ описывает изменения, внесённые в исходный репозиторий для инициализации источников данных, и порядок ручного запуска проекта.

## Что изменилось относительно исходного репозитория

### Документация схем

- Добавлена [карта исходных таблиц и типов](DATA_SOURCES.md) для трёх групп PostgreSQL-таблиц, четырёх ClickHouse-таблиц, MongoDB-коллекции и двух логических наборов Redis.
- В карте отмечены поля, которые присутствуют в DataFrame, но не перечислены в README: `shop_id` в истории заказов и `company_name` в истории цен конкурентов.

### Инициализация и загрузка

- В `scripts/init_raw_data.py` реализованы конфигурации подключений и запись DataFrame во все источники.
- Таблицы PostgreSQL создаются при первой загрузке, а при повторной загрузке заменяются данными заново.
- Таблицы ClickHouse создаются по DataFrame и заполняются; повторный запуск очищает таблицу перед вставкой.
- Коллекция MongoDB пересоздаётся и заполняется заново; создаётся составной индекс по `product_id` и `datetime`.
- Данные Redis хранятся в HASH-ключах `users_cities:{user_id}` и `users_clusters:{user_id}`. При повторном запуске удаляются только ключи этих двух наборов, остальные ключи Redis не затрагиваются.
- Хендлер ClickHouse распознаёт Python-даты и даты-время в колонках с типом `object`, чтобы создавать для них `DateTime64(6, 'UTC')`, а не `String`.

### Запуск и локальные файлы

- Добавлен [.env.example](.env.example) с локальными параметрами подключений и уменьшенными объёмами для первого запуска.
- В `compose.yaml` заданы локальные значения по умолчанию и healthcheck-и для пяти контейнеров.
- `make run` запускает `docker compose up -d --wait`, затем выполняет загрузчик из `.venv`.
- `.gitignore` исключает `.env`, `.venv`, локальные тома баз и настройки `.vscode` из Git.

В `.env.example` используются тестовые пароли `practice`. Используй их только для локального учебного окружения.

## Ручной запуск с чистого окружения

Нужны Docker с Compose v2, Python 3.12 или новее и `pip`.

Из корня репозитория выполни:

```sh
test -f .env || cp .env.example .env
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
docker compose -f compose.yaml up -d --wait
```

Затем загрузи данные вручную, явно передав переменные из `.env` процессу Python:

```sh
set -a
. ./.env
set +a
.venv/bin/python -m scripts.init_raw_data
```

Вместо создания окружения и установки зависимостей вручную можно выполнить `make init`, а затем `make run`. `make init` создаст `.venv` и установит зависимости из `requirements.txt`. `make run` поднимет контейнеры и запустит загрузчик автоматически; `.env` нужен, чтобы загрузчик использовал уменьшенные объёмы из примера.

## Объёмы данных и повторный запуск

В `.env.example` заданы:

```dotenv
UNIQUE_USERS_NUM=1000
UNIQUE_SHOPS_NUM=20
NUM_UNIQUE_INTERACTIONS=10000
```

Эти значения можно изменить в `.env`. Если удалить их из файла, скрипт возьмёт исходные значения: 1 миллион пользователей, 30 тысяч магазинов и 100 миллионов интеракций. Для первого локального запуска рекомендуется оставить уменьшенный набор.

Каждый запуск `scripts.init_raw_data` генерирует случайные данные заново и заменяет существующие наборы в SQL-таблицах и MongoDB, а также ключи соответствующих пространств Redis. Docker-контейнеры и их данные остаются запущенными/сохранёнными после загрузки. Остановить контейнеры без удаления данных можно командой:

```sh
docker compose -f compose.yaml down
```
